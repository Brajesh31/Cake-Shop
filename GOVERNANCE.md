# 🏛️ Project governance

## Maintainer
The repository is maintained by Brajesh Kumar through the GitHub account [@brajesh31](https://github.com/brajesh31). CODEOWNERS identifies the default reviewer.

## Decision making
- Small fixes may be proposed directly through a focused pull request.
- Significant product or architecture changes should begin with an issue or proposal.
- Security-sensitive changes require private coordination using SECURITY.md.
- Maintainers review scope, maintainability, accessibility, security, and documentation before merging.
- A pull request is not approved solely because automated checks pass.

## Contributions
Contributors are expected to follow CONTRIBUTING.md and CODE_OF_CONDUCT.md. The maintainer may request changes, defer a proposal, or close work that is outside project scope.

## Releases
The repository does not currently follow a fixed release cadence. Releases should be based on reviewed commits, successful checks, and a recorded deployment artifact. See docs/operations/release-rollback.md.

## Changes to governance
Propose governance changes through a pull request with a clear rationale. The maintainer makes the final decision for this repository.
